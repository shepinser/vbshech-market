# ВБШЕЧ

Локальный учебный интернет-магазин по макету владельца. Python + Flask, база **Microsoft Access** (`database.accdb`), подключение через `pyodbc`. Это самостоятельный проект, не сервис Wildberries.

## Запуск

1. Открыть `Запустить.bat`. При первом запуске устанавливаются зависимости в `.venv`.
2. Открыть в браузере http://127.0.0.1:5055.
3. Для первого администратора открыть `Создать администратора.bat`: указать email и придумать пароль. Можно повысить уже зарегистрированный аккаунт, указав его email. Команда работает только пока нет администратора.
4. Войти в этот аккаунт через обычную форму сайта. Открыть «Управление магазином».

Требуются Windows, Python 3.12+ и 64-битный драйвер `Microsoft Access Driver (*.mdb, *.accdb)`. На текущем компьютере драйвер установлен. Сервер доступен только на этом компьютере. Остановить его можно сочетанием Ctrl+C в окне запуска.

## Как проверить полный сценарий

1. Администратор создаёт пункт выдачи: город, адрес, часы работы.
2. Будущий сотрудник регистрируется как обычный покупатель.
3. Администратор назначает ему роль «Сотрудник ПВЗ» и конкретный пункт.
4. Покупатель регистрируется, добавляет товары в корзину, выбирает адрес и оформляет заказ.
5. Сотрудник в разделе «Рабочее место ПВЗ» нажимает «Принять в пункт выдачи».
6. Покупатель открывает «Мои заказы» и сообщает номер заказа и шестизначный код.
7. Сотрудник вводит код и нажимает «Выдать заказ». Статус становится «Выдан».

Для разных аккаунтов удобно использовать обычное окно браузера и окно инкогнито. Сотрудник видит только свой пункт; администратор видит все. Назначение администраторов выполняется через управление пользователями. Права проверяются сервером при каждом запросе.

## Устройство проекта

- `app.py` — Flask приложение, регистрация, вход и проверка пользователя.
- `commerce.py` — каталог, корзина, заказы, роли, отзывы и админка.
- `catalog_data.py` — получение категорий, фото, вариантов и рейтинга.
- `db.py` — подключение и транзакции Access.
- `init_db.py` — создание таблиц, связей и 8 демонстрационных товаров. Повторный запуск не очищает базу.
- `manage.py` — первоначальная настройка администратора.
- `templates/` — HTML-страницы с подстановкой данных из Python.
- `static/store.css` и `static/responsive.css` — оформление и адаптация к телефону.
- `static/photos/` — демонстрационные фотографии; `static/uploads/` — загруженные администратором снимки; `static/products/` — запасные иллюстрации.
- `check_project.py` — проверка на отдельной временной базе Access.

База: `Users`, `Categories`, `Products`, `CartItems`, `PickupPoints`, `OrderHeaders`, `OrderItems`. Внешние ключи настроены в самой Access, а не только в Python. Их можно увидеть через «Работа с базами данных → Схема данных → Все связи». В запросах JOIN есть поясняющие комментарии.

Цены заказа копируются из каталога в строки заказа при оформлении. Клиент не может подменить их формой. Корзина очищается в той же транзакции, в которой создаётся заказ. Повторная отправка формы защищена уникальным ключом оформления.

## Проверка

Из папки проекта: `.venv\Scripts\python.exe check_project.py`. Скрипт создаёт отдельную временную `.accdb`, проверяет роли, регистрацию, корзину, выдачу и связи; затем удаляет тестовую базу. Рабочие аккаунты не затрагиваются.

## Обновление интерфейса и магазина

Добавлены выбор города и адреса получения, каталог с подкатегориями, подсказки поиска, фильтры по цене, размеру, цвету и наличию. Избранное сохраняется в Access. На странице товара есть галерея фотографий, характеристики и выбор конкретного варианта. Добавление в корзину и избранное работает без перезагрузки страницы, с уведомлениями.

В «Управлении магазином» можно создавать и редактировать товары, загружать JPG/PNG/WebP, задавать цены, размеры, цвета, остатки и скрывать товар с сохранением истории заказов. Фотографии проверяются Pillow и сохраняются с новыми случайными именами. Указать нулевой остаток — отключить покупку варианта. «Заменить текущие фото» меняет галерею только при загрузке новых файлов.

При оформлении остатки резервируются в одной транзакции с заказом. При отмене до отправки они возвращаются. Повторная отмена не возвращает остатки ещё раз. Кнопка «Повторить заказ» добавляет доступные варианты в корзину по текущим ценам.

Администратор может отметить отправку заказа в ПВЗ. Сотрудник принимает заказ и выдаёт по шестизначному коду. У сотрудника есть поиск по номеру и фильтры статусов; в заказе сохраняется история с автором каждого действия. Покупатель видит код только после поступления в пункт. Код не выводится сотруднику заранее.

Отзывы разрешены только по полученным покупкам. Рейтинг считается из этих отзывов; прежние вымышленные оценки в интерфейсе убраны. На товар можно оставить один отзыв и затем изменить его.

Оформление: `static/store.css`, `static/responsive.css`, поведение: `static/app.js`. Предыдущий `style.css` больше не подключён. При настройке сокращённой анимации в ОС эффекты отключаются. На телефоне доступна нижняя панель навигации.

Миграция `migrations.py` сохраняет аккаунты и старые заказы. Перед обновлением сделана резервная копия `.backups/before-storefront-v2.accdb`. Копию с пользовательскими данными нельзя выкладывать в публичный GitHub.

Новые таблицы: `ProductVariants`, `ProductImages`, `Favorites`, `ProductReviews`, `OrderEvents`, служебная `SchemaVersions`. Связи настроены непосредственно в Access. Категории получили родительскую категорию, пользователи — сохранённый адрес.

Демонстрационные фотографии загружены с Unsplash и находятся в `static/photos/`; источники указаны в `ASSETS.md`. Иллюстративные фото не являются гарантией характеристик реального товара.

## Текущие границы

Это локальная учебная версия: нет реальных платежей, отправки email, настоящей логистики и возвратов. Остатки вариантов учитываются в Access. Поступление в ПВЗ отмечает сотрудник вручную. Email сохраняется, но владение почтой не подтверждается. Товары демонстрационные; каталог редактируется через админку. Для публичного запуска потребуется отдельная подготовка: HTTPS, ограничения попыток входа и выдачи, восстановление пароля и резервное копирование.

Документы находятся в папке `Документы`: описание проекта DOCX, презентация на 12 слайдов в PDF и PPTX, проект StarUML MDJ и JPG версии диаграмм. Скриншоты находятся в `screenshots`. Подробная инструкция — `Обзор ВБШЕЧ.html`, а также ссылка «Обзор сайта и инструкция» внизу сайта.

Репозиторий: https://github.com/shepinser/vbshech-market. Для публикации подготавливается отдельная чистая база: рабочий файл с аккаунтами и заказами не копируется. Перед публикацией исходников нужно убрать реальные аккаунты и заказы из базы; `.secret`, `.venv` и файлы блокировок в Git не добавляются.

Основные сценарии ориентированы на оформление заказа с получением в ПВЗ. Для справки: [портал обучения сотрудников WB](https://point-learning.wb.ru/) и [инструкции открытия ПВЗ](https://pvz.wb.ru/docs/Инструкция%20открытия.pdf). Собственные роли и статусы проекта упрощены для учебной задачи.
