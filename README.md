# ВБШЕЧ

Учебный интернет-магазин на Flask с настоящей базой Microsoft Access. Покупатель выбирает товар и ПВЗ, оформляет заказ и получает его по шестизначному коду. Реальных платежей нет.

## Запуск на Windows

Нужны Python 3.11 или новее и ODBC-драйвер Microsoft Access с той же разрядностью, что и Python. Для создания новой базы нужен установленный Access Database Engine с DAO.

В PowerShell из папки проекта:

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe app.py
```

Открыть [http://127.0.0.1:5055](http://127.0.0.1:5055). Если окружение уже установлено, достаточно последней команды. `app.py` создаёт недостающую базу, применяет миграции и запускает учебную доставку. Существующие аккаунты и заказы сохраняются.

Первый администратор:

```powershell
.\.venv\Scripts\python.exe manage.py
```

Команда предложит почту и пароль. Если аккаунт с такой почтой уже есть, назначит его администратором. Если администратор уже существует, новых сотрудников и администраторов назначают через сайт. Общего пароля администратора в проекте нет.

## Что проверить

1. Зарегистрироваться, выбрать город и пункт выдачи.
2. Найти товар по первым буквам, открыть карточку, выбрать размер и цвет.
3. Добавить в корзину. Кнопки минус и плюс сразу меняют количество и итог.
4. Оформить заказ и открыть «Заказы». Новый заказ сразу имеет статус «В пути».
5. Дождаться прибытия, скопировать шестизначный код.
6. После выдачи нажать «Оставить отзыв» у товара. Для возврата целого заказа выбрать «Оформить возврат» и подтвердить. Сотрудник принимает товары по тому же коду; до выдачи доступен отказ при получении.
7. Войти сотрудником ПВЗ или администратором, открыть «Работа в ПВЗ», найти заказ по коду и выдать.
8. В управлении магазином добавить товар или ПВЗ через всплывающее окно.
9. Из профиля покупателя подать заявку поставщика. Администратор одобряет её, после чего поставщик управляет своими товарами.

Пока `app.py` работает, раз в 30 секунд сервер выбирает **один случайный ожидающий заказ из всей базы** и делает его готовым к выдаче. Это не обещание доставки каждого заказа за 30 секунд. Браузер проверяет уведомления каждые 5 секунд. Сотрудник также может вручную принять заказ своего ПВЗ. Отмена доступна до прибытия и возвращает остатки. После выдачи покупатель подаёт заявку возврата целого заказа. Сотрудник того же ПВЗ принимает комплект по коду. Возврат и отказ при получении восстанавливают остатки один раз.

## Роли

| Роль | Возможности |
| --- | --- |
| Покупатель | Каталог, избранное, корзина, заказы, отзыв после выдачи, заявка поставщика |
| Сотрудник ПВЗ | Заказы своего пункта, приём и выдача по коду |
| Поставщик | Добавление, изменение и скрытие только своих товаров |
| Администратор | Каталог, категории, ПВЗ, роли, заявки поставщиков, все заказы |

  manage.py              первый администратор
  database.accdb         единственная рабочая база
  requirements.txt       зависимости Python
  ASSETS.md              источники изображений

## Как проходит запрос

HTML-форма отправляет POST в Flask. Сервер проверяет сессию, роль, CSRF-токен и поля, выполняет SQL с параметрами, затем подтверждает транзакцию. Jinja формирует HTML по данным Access. Корзина обновляется через `fetch`. `static/management.js` открывает формы управления в диалоге и заменяет содержимое списка после ответа сервера. При ошибке введённые данные остаются в открытом окне.

## Ограничения

Это локальная учебная система. Платёжного сервиса, проверки почты письмом, восстановления пароля и настоящей логистики нет. Адреса начальных ПВЗ вымышленные. Для публикации потребуется отдельная настройка сервера и защиты.

Файл `.secret` хранит локальный ключ сессий и создаётся автоматически. Его, `.venv`, кэш Python и блокировку `*.laccdb` не добавляют в Git. Рабочая база может содержать аккаунты и заказы: для публичного репозитория следует подготовить отдельную демонстрационную копию.
